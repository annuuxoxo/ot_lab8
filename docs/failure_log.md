# AI Failure Log

At least 3 cases where AI-generated code was wrong, unsafe, inefficient or misleading.

| # | Track | Tool | What the AI produced | How it was caught | Fix | Lesson |
|---|---|---|---|---|---|---|
| 1 | Setup | Claude Code (Opus 5.5) | Shell loop over a `$tracks` variable in zsh created a single directory named with the entire space-separated list instead of 10 directories | `ls` output showed one long folder name | Deleted it; re-ran the loop under `bash -c` (or use a zsh array) | Check generated shell commands against the actual shell (zsh ≠ bash word splitting); always inspect results with `ls` |
| 2 | Setup | Claude Code (Opus 5.5) | Used a shell variable named `path`; in zsh `path` is tied to `$PATH`, so every following command (`awk`, `cat`, `head`) was "not found" | Commands failed with exit 127 | Renamed the variable and ran the script under bash | zsh has special variable names (`path`, `status`…); avoid them in generated scripts |
| 3 | Setup | Claude Code (Opus 5.5) | Created the venv with the existing Miniconda Python, which is an Intel (x86_64) build under Rosetta → pip installed torch 2.2.2 (last Intel-Mac build) compiled against NumPy 1.x, which crashed with NumPy 2 | Import warning "module compiled using NumPy 1.x cannot be run in NumPy 2" + `file` showed x86_64 | Recreated the venv with Homebrew's native arm64 Python 3.12 → torch 2.15, no warnings | Check the interpreter architecture (`platform.machine()`) on Apple Silicon before installing compiled packages |
| 4 | B | Claude Code (Opus 5.5) | ILP code used `pulp.LpVariable(..., cat=...)` and `PULP_CBC_CMD`, but pip installed PuLP 4.2, which changed the API and no longer bundles a solver | 8 tests failed with TypeError / AttributeError | Pinned `pulp==2.9.0` (bundled CBC) in requirements.txt | Pin versions of libraries whose API the code depends on; AI knowledge of library APIs can be out of date |
| 5 | A | Claude Code (Opus 5.5) | Benchmark start point (1, 1): AdaGrad/RMSProp with lr = 1 step by exactly sign(g) and landed on the optimum in 2 iterations — a misleading "win" | Critical review of results: 2 iterations for AdaGrad on an ill-conditioned quadratic was implausible | Moved start to (1.3, 0.7); AdaGrad now 20 iterations | Suspiciously good results usually mean an artifact of the setup |
| 6 | A | Claude Code (Opus 5.5) | Compared empirical Fisher with the Hessian at w = 0, where for logistic regression they are identical — reported "0.01% difference" as if Fisher were an excellent approximation | Derived by hand: at w = 0, (p − y)² = p(1 − p) = 0.25 | Compare at the optimum w* instead → 26% difference | Check *where* an approximation is evaluated, not just the number |
| 7 | A | Claude Code (Opus 5.5) | Coarse learning-rate grid (×3 steps) made plain GD look better than preconditioned GD, because GD's best lr happened to be on the grid near its stability edge while the preconditioned methods' best lr fell between grid points | Result contradicted the condition-number reduction; swept lrs by hand | Used the same fine log grid (13 points) for every method; then verified the remaining GD advantage by eigen-decomposition (error has no component on the slow eigenvectors) | Unequal tuning resolution is an unfair comparison; explain surprising results with evidence before reporting them |
| 8 | C | Claude Code (Opus 5.5) | QAOA optimizer with only random restarts and a fixed iteration cap: p = 2 came out barely better than p = 1 (0.811 vs 0.811 at n = 8), which would wrongly suggest extra QAOA layers don't help | p = 2 contains p = 1 as a special case, so a worse/equal result means the optimizer failed | INTERP warm start from depth p−1 + maxiter 300·p → 0.811 / 0.865 / 0.902 | Check results against known properties (monotonicity in p) before interpreting them |
| 9 | C | Claude Code (Opus 5.5) | Same mistake as #7: QNG vs GD step-size grid stopped at 0.4, which was GD's best value, so QNG looked 2× faster | GD's best step was at the edge of the grid | Grid widened to 1.6: tuned GD and tuned QNG both need 6 steps, and QNG costs 40% more circuits per step | The AI repeated an earlier error: always check that the chosen hyperparameter is not on the edge of the grid |
| 10 | I | Claude Code (Opus 5.5) | QML comparison with default hyperparameters: quantum kernel scored 0.744 (feature scale too large → kernel oscillates) and the MLP underfit, giving a misleading ranking | Results inconsistent with known behaviour (MLP ≈ logistic regression on make_moons) | Same 5-fold CV tuning for every model, incl. the quantum kernel's feature scale; widened grids until choices were interior → quantum kernel 0.934 | Untuned baselines (or untuned quantum models) make any "advantage" claim meaningless |
